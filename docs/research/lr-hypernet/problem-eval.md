## 1. Problem Statement

- **要解决的问题**：构建一个**以双曲几何为核心的、全新的**事件点云分类架构，在 N-Caltech101 上**超过该数据集点云（point-based）范式的最好公开成绩**。

- **输入**：
  - 事件点云样本，每个事件为四元组 `(t, x, y, p)`
  - 归一化后：`t ∈ [0,1]`、`x/y ∈ [0, ~0.97]`、`p ∈ {−1, +1}`
  - 数据布局 `(B, N, 4)`（batch, 点数, 通道），当前 `N = 10240`
  - 主数据集 `ncaltech101_official_baidu/`：train `(3596, 10240, 4) float32`、test `(934, 10240, 4) float32`，101 类

- **输出**：
  - 样本级 / 视频级类别预测（101 类）
  - 可发表的交付物：新架构代码 + 训练/评测脚本 + 对齐协议下的对比表 + 3 种子均值±std

- **为什么重要**：
  - N-Caltech101 是事件点云分类的**主战场**，点云范式在该数据集上的公开最好成绩是 **SECNet 82.4%**（ICML 2026 原文报告）
  - 追赶者少：点云范式在该数据集上**几乎没有第三个可比的公开结果**，EFV++/RBE 的 89.76% 属**其他范式**，不构成本项目的 SOTA 门槛
  - 目标会议 CVPR，novelty 量级要求高于 CCF-A（学长明确："比 FSE 量级高很多"）

### 1.1 目标数值（已确认，无其他要求）

| 数据集 | 要超过的最好吗成绩 | 来源 | 备注 |
|---|---|---|---|
| **N-Caltech101（主）** | **82.4%** | SECNet 原文报告（两阶段协议） | 本项目唯一硬指标 |
| CIFAR10-DVS（次） | 75.7% | SECNet 原文报告 | 点云范式唯一点；全范式 SOTA 为 NGN 87.35%，**不是**我们的门槛 |

- **架构要求**：必须是**全新的架构**，可**集百家之长**（允许复用 SECNet 的傅里叶聚合、RP1 选点、时间编码等已有组件）。
- **无其他附加要求**：不要求协议对齐、不要求参数对齐、不要求只改一处。

### 1.2 由目标数值推出的关键推论（重要）

**单窗协议的天花板约 60%**（SECNet 论文 Table 9 自测：300ms 单窗 60.04%/60.60%），而 82.4% 是**两阶段协议**（单窗训练 + 跨窗口聚合分类器）的结果。

> 因此：**"超过 82.4%" 只能在两阶段协议下达成。**
> 这不是额外的要求，是目标数值本身决定的。**新架构必须服务于跨窗口聚合**——只在单窗上做架构对比，物理上碰不到 82.4%。

## 3. Success Criteria

- **主要指标**：N-Caltech101 上的分类准确率，**> 82.4%**（点云范式公开最好成绩）
- **阈值**：**严格大于** 82.4%。等于不算成功（原文报告的是其自身成绩，持平无贡献可言）
- **次要指标**：
  - CIFAR10-DVS > 75.7%
  - 参数量 < 3.5M
  - 主表报 **3 种子均值 ± std**（934 样本 test，单种子不可信）
- **统计功效约束（必须遵守）**：
  - N-Caltech101 test 仅 **934 样本，95% 置信区间 ±3.2%**
  - **< 1% 的差异统计上不可区分**——现有组件筛选结果（+0.43 / +0.21 / +0.96 / +2.36 / +3.32）**全部落在噪声带内**，只能作方向性参考
  - **禁用 best-on-test**：一律报 **ep60 准确率**或**最后 5 epoch 均值**
  - **配对种子**：baseline 与候选使用**同一组种子**，报配对差值（比独立多种子省一半以上算力）
  - **粗筛提前停**：阶段二粗筛用 30–40 epoch，仅对 top-1 跑满 60 epoch

### 3.1 ⚠️ eval 非确定性（2026-10-13 发现，比样本量噪声更严重）

**根因**：`models/modules.py:66` 的 `furthest_point_sample` 用 `torch.randint(0, N)` **随机选 FPS 起始点**；训练脚本只在 `main()` 开头设一次 `torch.manual_seed`，训练持续消耗 RNG，因此**每个 epoch 的 eval 都用不同的随机态**。

**实测同一 checkpoint 的 eval 波动**：

| 来源 | baseline Test Acc |
|---|---|
| 训练日志 ep60 | 47.323% |
| CPU 推理（无固定种子）×3 | 48.715 / 48.073 / 47.645% |
| **固定 eval_seed=42** | **46.146%** |

**FPS 噪声跨度 ≈ 2.6pp**，**与所有组件效应（+0.43 ~ +3.32pp）同量级**。

> **推论**：第一阶段的组件排名**被 FPS 噪声严重污染**，单次读数的 +Δ 不能作为有效性依据。这比"934 样本 ±3.2%"是**更严重**的问题——样本量噪声可以靠多采样降低，而 FPS 噪声是**每次 eval 换一个随机几何**。

**修正后的评测协议（强制）**：

1. **固定 eval 种子**：所有对比必须在**同一 eval_seed** 下推理（`tools/extract_preds.py --eval_seed`）
2. **配对显著性检验**：用 `code/analysis/mcnemar_test.py` 做逐样本 McNemar（配对，比两个聚合数字信息量大得多）
3. **多种 eval 种子复核**：至少 3 个 eval_seed 重复，结论需**跨种子一致**才算成立（单种子结论只能作参考）
4. **论文级**：多种子（训练种子）× 多 eval 种子的均值 ± std，且**必须报告 eval 噪声量级**作为方法论诚实性证据

> 这条发现本身是**有价值的负面结果**，应写入论文的实验设置/局限性章节："该基线的评测协议存在 FPS 采样不确定性，我们通过固定种子 + 配对检验 + 多种子复核来控制"。

## 4. Verifier / Evaluator

- **判分方式**：自动（脚本）+ 人工复核协议一致性
- **判分逻辑**：
  1. 训练完成后在 test split 上评测，取 **ep60 准确率**（或最后 5 epoch 均值）
  2. 三种子重复，报均值 ± std
  3. 对比对象为**原文报告的公开成绩**（SECNet 82.4% / 75.7%）
- **已知局限（必须写进论文，不能隐瞒）**：
  1. **协议差异**：我们用的是百度盘单窗数据（train 3596 / test 934），论文 Table 1 用三窗（20896 / 5226）。数据划分 `np.random.shuffle` **未设种子，不可复现**
  2. **官方 checkpoint 架构与本地代码不匹配**（attention 1080 vs 540；classifier 3240→1024→101 vs 1080→256→101）
  3. **官方第二阶段聚合模型与训练脚本未公开**，`train_frequency.py` 的 `num_category choices=[10,40]` 跑不了 101 类
  4. **GitHub 0 fork、6 篇引用无复现报告、全网无第三方复现**
  5. 因此若声称"超过 82.4%"，**必须同时给出对齐协议下的重训对照**（"† our re-implementation"脚注），否则数字不可比
- **给论文的可辩护性要求**：仓库缺陷需作为 due diligence 证据写进附录

## 5. Hack Path Analysis

| 可能的 hack 方式 | 如何防范 |
|---|---|
| **测试集泄漏**：用 test 调超参、选 checkpoint、选架构 | 所有超参与架构决策只在 train/val 上定；报 ep60 而非 best-on-test；保留每次实验完整日志与配置 |
| **best-on-test 挑选**：从 60 个 epoch 里挑最高那个报 | **禁用**。统一报 ep60 或最后 5 epoch 均值 |
| **单种子挑选**：跑多个种子只报最好的 | 固定 3 个种子全部报告，报均值±std；种子集合写进 config |
| **协议不对齐**：拿单窗成绩与 SECNet 两阶段 82.4% 直接比 | 必须标注协议；给出对齐协议下的重训对照 |
| **组件叠加当架构**：把 SECNet + 几个插件直接叫"新架构" | §6 的可检验标准：整体形态必须独立于 SECNet，不能是原样加插件 |
| **数据增强/额外数据充数**：用外部数据或 test 时间增强抬分 | 主表只用官方协议数据；任何额外数据必须单列并标注 |
| **曲率/数值技巧掩盖失败**：靠 clip、NaN 兜底让曲线好看 | 记录并公开所有数值兜底手段（atanh clamp、loss 有限性检查、grad clip 5.0） |
| **只报有利数据集**：两个数据集只报好的那个 | 两个数据集都报 |

## 6. Approach（1–5 完成后才展开，以下为方向约束，非最终设计）

### 6.1 组件筛选阶段已确认的素材（2026-10-13 状态）

| 组件 | 结果 | 对第二阶段的意义 |
|---|---|---|
| 傅里叶聚合 | 替换掉 ~10 点 | **保留**。聚合层可以是傅里叶（用户 2026-10-13 确认） |
| 双曲注意力（Lorentz 距离） | 旧代码 +2.36pp；新代码 172245 验证中 | 最强双曲候选，但**属"外挂件"**，回答不了"双曲核心是什么" |
| 双曲选点（Poincaré 等双曲面积网格） | 旧代码 +3.32pp；新代码 172274 排队 | 同上 |
| 双曲嵌入层 | 旧版 +1.07pp **实为残差瓶颈**；真双曲运算仅 +0.21pp | **判无效**，剔除 |
| 双曲分类头 | −3.00pp | 无效（logits 量级问题） |
| 傅里叶+双曲融合（门控残差） | −1.61pp | 无效 |
| MambaSSM / KDA | 0.00pp / 梯度爆炸 | 放弃 |
| time_enc / RP1 选点 | +0.43pp / +0.96pp | 方向性有效，可选素材 |

### 6.2 主线候选：双曲频域聚合

**把傅里叶搬到双曲切空间做**：邻居经 `log_map` 统一映射到**组中心的切空间**，在切空间做空间/时间傅里叶（FFT），再 `exp_map` 映回。

- 满足"聚合层可以是傅里叶"：傅里叶仍在，只是换了作用域
- 满足"双曲是核心"：双曲不再是外挂残差，而是承载聚合的几何
- 满足"全新架构"：整体形态从欧氏编码器变为双曲编码器
- 文献空白：双曲 + 频域几乎没有工作

**技术风险（唯一但关键）**：同一组的邻居必须映射到**同一个**切空间（组中心），否则"在切空间做 FFT"无意义。需验证数值稳定性（exp 饱和、atanh 边界梯度尖峰）。

### 6.3 次要候选

1. **可学习曲率**（CurvatureAwareOpt 思路，尚未尝试）：成本最低，与双曲注意力天然搭配
2. **双曲原型/对比度量**：此前失败的是双曲**分类头**（logits 量级崩），换成度量学习损失是另一回事，未试

### 6.4 "不是 SECNet 换皮"的可检验标准（必须守住）

允许复用傅里叶聚合、RP1 选点、时间编码——但**整体形态必须独立**。判定条件：

- 不能是"SECNet 原样 + 双曲插件"（即：去掉双曲模块后，剩下的部分就是完整的 SECNet）
- 编码器/聚合/分类三个环节中，**至少两个**的形态与 SECNet 有实质差异
- 消融表里必须能回答"你的双曲核心贡献是什么"，答案不能只是"+2.36pp 的注意力权重"
- 架构图与 SECNet 论文图并排看，不应呈现"同一骨架 + 附加模块"

### 6.5 必须服务跨窗口聚合（由 §1.2 推论强制）

单窗天花板约 60%，82.4% 只能两阶段拿到。因此新架构设计从一开始就要考虑：

- 跨窗口特征如何聚合（SECNet 用 3×1080→1024→101 的简单分类器）
- 双曲几何能否在**跨窗聚合**这一层发挥作用（层级/树状结构在视频级样本上信号更强）
- **可证伪的机制假设待检验**：双曲在单窗上增益弱（都在 ±3.2% 噪声内），可能因为单窗把层级结构压扁了——一条样本只有一个 30ms 窗口，`mark` 全唯一，双曲擅长建模的树状关系没有信号。若换到跨窗/视频级协议后双曲增益明显变大，此假设成立

### 6.6 待确认项（不阻塞，但影响设计）

- [ ] 双曲在哪一层承担"核心"角色：聚合层（6.2）还是跨窗聚合层（6.5）
- [ ] 阶段二的算力缺口：6 变体 × 3 种子 × 60ep ≈ 100 GPU-小时，当前排不上；需靠"提前停 + 配对种子"压缩
- [ ] CIFAR10-DVS pipeline 尚未搭建
