# Claude 实验设计分析（2026-10-11）

> 来源：HPC 上 Claude CLI（glm-5.3-shouyun），输入当前全部实验状态，输出逐条分析。

## 核心结论

### 1. 30ep/b8 看不出组件级差异

**判据不是 epoch 数，而是是否收敛。** 当前所有 b8 变体 Train <40%，处于严重欠拟合区——此时比较的是"早期学习速度"，与最终性能相关性很弱（组件可以帮早期、伤最终，反之亦然）。

两条路任选其一：
- (a) 修好优化，让 30ep 内 Train 到 plateau
- (b) 保持现配置但跑到 Train 停止上升为止（可能需要 80-120ep）

**更严重的问题：对照没对齐。** euclidean 只有 epoch4，baseline b8/30ep 只到 epoch2，跨 epoch 单点比较无效。

统计功效：test 只有 934 样本，acc 的 95% CI 约 ±3%。31 vs 24 可以下结论；31 vs 29 不行。组件间差异 <3% 必须跑 2-3 seeds。

### 2. 欠拟合是优化问题，不是容量问题

容量可以排除：5类 sanity 到 81%，baseline b32/150ep Train 99.86%——同一架构能拟合 101 类。

按嫌疑排序：

1. **BatchNorm + b8（最大嫌疑）**：b8 下统计量噪声极大，长尾数据下一个 batch 几乎全是头部类。修复：BN → GroupNorm（`nn.GroupNorm(32, C)`）。不碰任何被测组件，只是让 b8 可用。
2. **有效学习率错位**：LR 沿用 b32 配方，用 gradient accumulation ×4 凑等效 b32。
3. **可学习曲率拖慢收敛**：打印曲率 c 轨迹——c→0 说明模型在"逃离"双曲几何（重要信号）；c 震荡就加 warmup：前 10ep 冻结 c=1，之后单独 param group（lr=1e-3），clamp 到 [0.1, 10]，**不要对 c 施加 weight decay**。
4. **长尾**：尾类只有 5 个样本，普通 CE 基本学不到。用 WeightedRandomSampler（权重 1/n_c）或 logit-adjusted CE：`loss = CE(logits + τ·log prior)`，τ≈1。

**零成本诊断**：看 v3.1 的 per-class Train acc。头部类 50-60% 而尾类全 0 → 长尾+BN 问题；全类均匀低 → LR/曲率问题。

### 3. "双曲翻盘靠稀有类"假设可以现在检验

链条不完整但值得检验。双曲理论优势来自"对层次/树结构低失真"，不是"样本少"——稀有类不天然是层次的。合理机制是间接的：双曲体积指数增长 → 低维下 101 类可分性更好、少样本下决策边界 margin 更大。

**现在就能做，不用跑训练**：v1（Poincaré，38.33%）和 baseline b32/150ep 都已完成，直接对两个 checkpoint 做分桶 per-class 分析：
- 桶：head（train >100）/ mid（30-100）/ tail（<30），比较桶级 macro acc
- 若 v1 增益集中在 tail → 假设成立
- 若增益均匀或只在 head → 双曲只是正则化作用，叙事要换
- 尾类每类测试样本约 5 个，单类无统计意义，**必须看桶级聚合**

### 4. 下一步（按优先级）

1. **今天、零 GPU 成本**：分桶分析 + v3.1 曲率轨迹 + v3.1 per-class Train acc。分别回答"假设是否成立""几何是否被使用""欠拟合根源"。
2. **本周、修优化器**：BN→GroupNorm + grad accum ×4 + balanced sampler + logit-adjusted CE + 曲率 warmup。先跑欧氏 baseline 60ep，确认 Train >95%，以此为新对照组——**欠拟合没修好之前，任何新组件实验都是浪费卡时**。
3. **补齐对照**：euclidean control 和 baseline b8/30ep 跑完。
4. **v3.1 拆变量**：目前 v3.1 = Lorentz + time_enc + 曲率优化，一次改了 3 个变量，无法归因。拆成 Lorentz(fixed c) → +curvature → +time_enc 三步递进。
5. **报告协议**：micro + macro 双指标，关键对比跑 2-3 seeds，差异 <3% 不下结论。

### 警惕信号

v1 Poincaré 30ep 到 38.33%，v3.1 Lorentz 13ep 才 31.16%。如果修好优化后 Lorentz 仍慢于 Poincaré，和"Lorentz 数值更稳"的直觉相反，优先查 Lorentz 实现：exp/log map 是否处理了 ‖x_t‖≤√c 的退化点、tangent 投影顺序、梯度 clipping 位置。
