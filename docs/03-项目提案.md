# EventHyperPoint：事件点云的双曲 Point-based 表示学习

> 项目 Proposal v0.1 | 2026-10-05
> 状态：方向确认，待细化方法与实验

---

## 1. 一句话定位

**不建图，直接在事件点云上做双曲几何运算——用双曲空间的指数级容量建模事件流的天然时空层级结构。**

---

## 2. 问题定义

事件相机输出异步事件流 $\mathcal{E} = \{e_k = (x_k, y_k, t_k, p_k)\}_{k=1}^N$，具有微秒级时间分辨率和高动态范围。事件流天然具有**多层级时空结构**：

```
场景 → 物体 → 部件 → 事件簇 → 单个事件
```

现有事件表示学习方法分为三条路线，但都存在本质不足：

### 路线 A：Dense-based（Event Frame / Voxel Grid / Time Surface）
- 将事件聚合为 2D 帧或 3D 体素，牺牲了事件的稀疏性和细粒度时间信息
- 计算开销大，与事件相机的低功耗设计矛盾

### 路线 B：Graph-based（AEGNN / ECAF-GCN / EHGCN）
- 先将事件构建为图（radius_graph / KNN / hyperedge），再做图卷积
- **建图步骤引入信息损失**：边的构建依赖固定半径或 K 值，无法自适应事件密度变化
- 跨空间注意力 $O(N^2)$ 复杂度，难以扩展到长序列高分辨率
- 双曲 GCN（ECAF-GCN/EHGCN）虽引入双曲空间，但仍受限于图结构的中间表示

### 路线 C：Point-based（SpikePoint / EventMamba / SECNet）
- 直接将事件作为点云处理，保留稀疏性和时间信息
- **但全部在欧氏空间中操作**：FPS 采样、KNN 分组、注意力聚合均使用欧氏距离/点积
- 欧氏空间的多项式体积增长无法高效表达事件的层级结构，深层网络需要大量参数才能拟合层级依赖

---

## 3. 核心洞察（Motivation）

### 3.1 事件点云为什么需要双曲空间？

1. **天然层级结构**：事件流的时空组织是树状的（场景→物体→部件→事件簇），双曲空间具有**指数级体积增长**，能以低维嵌入表达高维层级数据，而欧氏空间需要指数级维度才能做到

2. **PointNet++ 式分组本身就是层级树**：FPS 选中心点 → KNN 分组 → 下一层再 FPS → 再分组，每一层抽象一级。这种递归分组在欧氏空间中是"近似"层级，在双曲空间中是"天然"层级

3. **时间维度加剧层级性**：事件不仅有空间层级，还有时间层级（毫秒级运动→秒级动作→分钟级场景），4D 时空点云的层级结构比普通 3D 点云更复杂，双曲空间的优势更明显

### 3.2 为什么不直接用 GNN+双曲？

- ECAF-GCN / EHGCN 证明了双曲空间对事件感知有效，但它们的**建图步骤是瓶颈**：固定半径图无法适应事件密度变化，超图构建依赖光流估计（额外计算开销）
- Point-based 方法跳过建图，直接在原始事件上操作，**双曲运算可以直接作用于点云**，避免中间表示的信息损失

### 3.3 为什么不直接用普通点云+双曲（PointCHR）？

- PointCHR (ICML 2026) 只做**曲率感知的双曲整流**（把高曲率点投影到双曲边界），不是完整的双曲 point-based 架构
- PointCHR 处理普通 3D 点云（x,y,z），不处理事件的时间维度和极性
- 事件点云的异步性和时间层级需要专门设计

## 4. 方法框架（初步设计）

以 EventMamba 的层次结构为骨架，将每个模块的欧氏运算替换为双曲运算：

```
Event Stream → 双曲下采样 → Hierarchy(m stages) → 双曲分类头
                           ↓
            Stage: 双曲 LocalFE → 双曲 TAG → 双曲 GlobalFE
```

### 4.1 双曲事件预处理

- 事件归一化后，通过**指数映射** $\exp_c^0$ 从欧氏切空间映射到 Poincaré ball
- 时间维度作为点的第 4 维，在双曲空间中与空间维度联合建模

### 4.2 双曲 LocalFE（替换 FPS+KNN+ResBlock）

| 模块 | 欧氏版（EventMamba） | 双曲版（我们的） |
|---|---|---|
| 采样 | FPS（欧氏最远点） | **双曲 FPS**（Poincaré 距离最远点） |
| 分组 | KNN（欧氏 K 近邻） | **双曲 KNN**（双曲距离 K 近邻） |
| 标准化 | 组内均值+标准差 | **双曲中心化**（gyromidpoint + 双曲距离标准化） |
| 特征变换 | MLP + BN | **双曲线性层**（Möbius 矩阵乘法 $\mathbf{W}\otimes_c \mathbf{h} \oplus_c \mathbf{b}$）+ 双曲 BN |

### 4.3 双曲 TAG（时间注意力聚合）

- 欧氏版：$A = SoftMax(MLP(S))$，$SA = S \cdot A$
- 双曲版：**双曲注意力**（基于双曲距离的相似度矩阵），沿时间轴聚合 K 个最近邻特征
- 利用双曲空间的各向异性度量，增强时间维度上的层级区分

### 4.4 双曲 GlobalFE（全局建模）

- 欧氏版：Mamba SSM（线性复杂度长序列建模）
- 双曲版：**双曲 SSM / 双曲 Mamba**——在 Poincaré ball 上定义状态空间模型，$h_t = \bar{A}\otimes_c h_{t-1} \oplus_c \bar{B}\otimes_c x_t$
- 或先用双曲注意力聚合，再对数映射回欧氏做 Mamba（混合方案，降低实现难度）

### 4.5 双曲分类头

- 双曲 logits：$\log_c^0(\mathbf{h})$ 映射回切空间，再接欧氏 FC
- 或直接在双曲空间做分类（双曲 softmax / 原型分类）

## 5. 与现有工作的本质区别

| 维度 | ECAF-GCN / EHGCN | SpikePoint / EventMamba / SECNet | PointCHR | **EventHyperPoint（我们的）** |
|---|---|---|---|---|
| 表示 | 图 / 超图 | Point Cloud | Point Cloud（3D） | **Point Cloud（4D 时空）** |
| 空间 | 欧氏+双曲 | 欧氏 | 欧氏+双曲（整流） | **欧氏+双曲（全架构）** |
| 建图 | 是（radius/hyperedge） | 否 | 否 | **否** |
| 时间建模 | 边属性 / 光流 | t 坐标 + Mamba | 无（3D 点云） | **双曲时空联合建模** |
| 双曲深度 | 双曲 GCN 分支 | 无 | 仅曲率整流 | **双曲采样+分组+聚合+全局** |
| 复杂度 | $O(N^2)$ 注意力 | $O(N)$（Mamba） | $O(N\log N)$ | **目标 $O(N\log N)$** |

## 6. 实验计划

### 6.1 数据集
- **N-Caltech101**（分类，101 类）——与 EventMamba/SECNet 对齐
- **N-Cars**（分类，2 类）
- **DVS128 Gesture**（动作识别，11 类）
- **Gen1**（检测，可选）

### 6.2 基线
- Point-based 欧氏：SpikePoint、EventMamba、SECNet
- GNN+双曲：ECAF-GCN（我们的复现）、EHGCN
- 普通点云+双曲：PointCHR（适配到事件数据）

### 6.3 消融实验
- 双曲 FPS vs 欧氏 FPS
- 双曲 KNN vs 欧氏 KNN
- 双曲注意力 vs 欧氏注意力
- 曲率敏感性（不同 init curvature）
- 双曲深度（1层 vs 2层 vs 全双曲）

### 6.4 评估指标
- 分类准确率 / mAP
- 参数数量 / FLOPs
- 推理延迟
- 层级结构可视化（t-SNE / 双曲嵌入可视化）

## 7. 风险与挑战

| 风险 | 应对 |
|---|---|
| 双曲 KNN 计算效率低 | 用近似最近邻（双曲 LSH）或先欧氏粗筛再双曲精排 |
| 双曲 SSM 实现复杂 | 先用混合方案（双曲聚合 + 欧氏 Mamba），再逐步双曲化 |
| 曲率学习不稳定 | 用 softplus+0.05 保正（ECAF-GCN 经验），曲率 init 0.2-0.8 敏感性低 |
| 与 EventMamba/SECNet 比性能不升反降 | 先在小数据集（N-Cars）验证，再扩展 |
| 双曲梯度爆炸/消失 | 用 exp/log 映射钳制，gradient clipping |
