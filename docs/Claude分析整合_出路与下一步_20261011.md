## 二、Claude 的核心判断

### 1. 双曲无增益时的三条出路

**路线 A（推荐）：双曲搬到分类头**
- Backbone 保持欧氏远程聚合，分类头换成双曲原型分类器
- 理由：双曲增益在文献中最常出现在嵌入/分类层，N-Caltech101 类别有 WordNet 层级结构
- 成本极低：只改分类头，可从已训 backbone finetune
- 可视化：Poincaré 盘投影 + 层级聚类结构

**路线 B（备选）：受控分析 + 复现性论文**
- 独有资产：SECNet 代码不完整的完整证据链 + 同预算受控组件研究
- 上限取决于 venue 有没有 benchmark/analysis track

**路线 C（不推荐）：时间编码当主线**
- 有用但预期增益小，撑不起顶会主线

### 2. 欠拟合的根因与修复

- BN 在 b8 下统计噪声大 → GroupNorm 修复（已在跑）
- 有效 batch 太小 → GradAccum4（已在跑）
- 数据增强缺失：官方生成脚本带 random_crop + reverse_T，百度单窗数据没有
- 学习率/初始化可能需要调

### 3. 跑多少轮能看出效果

- 30ep/b8 只能筛大效应（≥5pp），不能下"无差异"结论
- 决定性实验需要 Train acc ≥95%
- 建议两层结构：筛选层（30ep，多配置）→ 确认层（100ep，只跑2-3个配置）

### 4. 第二数据集：CIFAR10-DVS（高置信度）

- 10类，跑得快，社区认可度高
- point-based 落后全范式 11.6 点（75.7 vs 87.35），有增益空间
- DailyDVS-200 是陷阱（无基线、200类小数据方差大）

### 5. 82.4% 两阶段协议

- 官方 checkpoint 结构已透露设计：3×1080 → 1024 → 101
- 冻结 backbone，3窗特征拼接训小 MLP，工程量 2-3 天
- 这是把 69.6% 推向 75+ 的最短路径

## 四、论文底线

- **及格线**：主协议打平（±0.5）+ 至少一个次级维度明确赢（长尾类、低点数、效率）
- **理想线**：至少一个数据集涨 1.5+ 点，另一个打平
- **不能发**：主表输给基线 2-3 点，任何可视化/理论都救不回来

## 五、关键教训

1. 每个架构变体必须配同预算的基线对照（之前缺失，已补上 b8/30ep 基线）
2. 30ep 结论不能直接写论文，需要 100ep 确认
3. 双曲用在聚合层是弱位置，分类头才是双曲增益的常见位置
4. 单窗 54% 是自曝短板的协议，主表应该用三窗+投票/两阶段
