## 一、项目概述与目标

### 1.1 核心目标
构建一个以双曲几何为核心的全新事件点云分类 SOTA 架构，最终发表时完全看不出是基于 SECNet 的改进。目标会议 CVPR。

### 1.2 当前阶段
组件筛选阶段——在 SECNet 原始傅里叶聚合不动的前提下，逐个验证组件有效性，筛选有用组件，为最终全新架构提供素材。

### 1.3 两阶段路线
1. 组件筛选阶段（当前）：SECNet 原始傅里叶聚合不动，每次只加一个组件，60 epoch 看相对排序
2. 架构整合阶段（下一步）：基于有效组件 + 双曲核心，设计全新架构（聚合方式不能是傅里叶），再做消融

### 1.4 最终架构候选方向
- 双曲嵌入为核心：输入→双曲映射→双曲局部+远程聚合→双曲原型分类
- 双曲频域聚合：傅里叶思想扩展到双曲空间
- 双曲 Mamba/SSM：双曲状态空间模型替代傅里叶
- 16 点选择+双曲聚合：RP1 选点前端 + 双曲注意力后端
- 傅里叶+双曲并行融合：保留傅里叶聚合，叠加双曲聚合分支，门控残差融合

## 二、技术背景与核心概念

### 2.1 SECNet 核心机制
SECNet（Scalable Event Cloud Network，ICML 2026，arXiv 2412.20803）的精髓是两次傅里叶变换：
1. 空间域傅里叶变换：对每个 group 的 K 个邻居特征做 FFT，提取空间频率特征
2. 时间域傅里叶变换：对 group 维度做 FFT，提取时间/全局频率特征
3. 两次加权和聚合：空间频率特征 + 时间频率特征加权求和

关键发现：替换这个傅里叶聚合为自定义欧氏/双曲聚合会掉约 10 个点（23.98% vs 33.83%），所以组件筛选阶段绝对不替换傅里叶聚合。

### 2.2 双曲几何核心概念
- Poincaré 球模型：单位球内的双曲空间，距离公式 d(x,y) = (1/sqrt(c)) * acosh(1 + 2c||x-y||^2 / ((1-c||x||^2)(1-c||y||^2)))
- Lorentz 模型：双曲空间的另一种表示，数值更稳定
- 指数映射 exp_map：欧氏切空间 -> 双曲空间
- 对数映射 log_map：双曲空间 -> 欧氏切空间
- Möbius 加法：双曲空间中的向量加法
- 曲率 c：可学习参数，控制双曲空间弯曲程度
- 双曲优势：树状/层级结构在双曲空间中可指数级容量嵌入（Sarkar 2011），N-Caltech101 类别有 WordNet 层级结构

### 2.3 事件点云数据格式
- 每个事件 = (t, x, y, p)，t=时间戳，x/y=像素坐标，p=极性(±1)
- 归一化后：t∈[0,1]，x/y∈[0,~0.97]，p∈{−1,+1}
- 每个样本采样 10240 个点
- 数据布局：(B, N, 4) = (batch, num_points, channels)

### 2.4 标准消融配置（所有组件实验必须一致）
数据：ncaltech101_official_baidu/{train,test}.h5
  train (3596,10240,4) float32, test (934,10240,4) float32
  布局 (t,x,y,p)，p∈±1，101类，mark全唯一
batch_size=8, grad_accum=4
  注意：只等效梯度，BN按micro-batch=8估计，不等效b32
epoch=60, seed=42
optimizer=AdamW lr=0.001 wd=1e-4
scheduler=CosineAnnealingLR
num_point=10240, num_category=101
无 group_norm、无 aug、无 dropout
label smoothing eps=0.2
单轮约5分钟，60轮约5小时

## 四、组件实现细节（逐个）

### 4.1 time_enc（多频 sin/cos 时间编码）
- flag：--time_enc
- 代码位置：FECNet.py 嵌入层
- 实现：对时间戳 t（通道0）做多频 sin/cos 编码，频率 2^0–2^3，生成 8 维 + 原始 4 维 = 12 维输入 embed
- 公式：embed_in = [x, y, p, sin(2πf·t), cos(2πf·t)] for f in [1,2,4,8]
- 效果：+0.43pp（47.97% vs 47.54%），语义等价不受修复影响
- 结论：方向性有效，但增益小

### 4.2 RP1 选点（spatial-uniform 16点选择）
- flag：--rp1_selector
- 代码位置：FECNet.py:249-292（RP1SpatialUniformGrouper）
- 实现：替换 FPS 采样为 x,y 空间均匀网格选点，每个 stage 的 group center 从空间均匀分布的网格中选取
- 来源：event-camera-rps 论文（RP1 = Representative Point Selection）
- 修复B影响：选点坐标从 fps_parameter 缩放后改为缩放前原始 xy
- 效果：旧代码 +0.96pp（48.50%），新代码重测中（172257）
- 注意：eval 时选点也是随机的（torch.rand），测试精度有噪声 <±0.5%

### 4.3 双曲选点（Poincaré 盘等双曲面积网格）
- flag：--hyperbolic_selector
- 代码位置：FECNet.py:301-340（HyperbolicSpatialUniformGrouper）
- 实现：在 Poincaré 双曲盘上按等双曲面积划分网格选点（外圈更密），是 RP1 的双曲对照
- 学长会议核心探索点："欧氏 vs 双曲选点，特征可能不一样"
- 修复B影响：选点坐标改为缩放前原始 xy
- 效果：旧代码 +3.32pp（50.857%，epoch50），新代码重测中（172274）
- 与 rp1 互斥：都替换 local_grouper，不能同时开

### 4.4 双曲注意力（Lorentz 距离替代欧氏距离）
- flag：--hyperbolic_attention
- 代码位置：FECNet.py:559-590（HyperbolicAttention）、842-844（forward 调用）
- 实现：在傅里叶聚合输出后，用 Lorentz 双曲距离计算注意力权重，0.1 小权重残差注入
  x_hyper = self.hyper_attns[i](x, x, x)  # (B, S, C)
  x = x + 0.1 * x_hyper
- 距离公式：Lorentz 距离 d_L(x,y) = acosh(-<x,y>_L)，带 1/sqrt(c) 缩放
- 参数：每 stage 只有曲率 c 和温度 T 两个标量参数（无 QKV 投影）
- 修复C影响：初始曲率从 softplus(0.4)=0.913 改为真正的 0.4
- 效果：旧代码 +2.35pp（49.89%，最强组件），新代码重测中（172245）
- 显存：[B,S,S] 距离矩阵，stage0 S=2048，b8 下约 134MB

### 4.5 双曲嵌入层（exp/log map 双曲组织特征）
- flag：--hyperbolic_embedding
- 代码位置：FECNet.py:520-550（HyperbolicEmbedding）
- 实现（修复后，Ganea 2018 标准做法）：
  1. 进球前尺度归一：x = x / norm(x) * sqrt(dim)
  2. exp_map 进入双曲空间
  3. 双曲线性变换：exp(W · log(p))
  4. Möbius 偏置（零初始化）
  5. log_map 回欧氏空间
- 旧版 bug：log_map(exp_map(x)) ≡ x 恒等变换，双曲部分完全无效，+1.07pp 实际是残差瓶颈效果
- 修复C/E影响：初始曲率语义 + 进球前尺度归一
- 效果：旧版 +1.07pp（有恒等bug），修复版重测中（172206）
- 关键判断点：如果修复版≈48.6%说明增益来自残差结构本身；如果明显更高说明双曲还有额外增益

### 4.6 双曲分类头
- flag：--hyperbolic_classifier
- 实现：可学习双曲原型，logits = −双曲距离
- 效果：-3.00pp（44.54%），logits 量级问题
- 结论：无效，不再尝试

### 4.7 傅里叶+双曲融合
- flag：--hyperbolic_fusion
- 实现：保留傅里叶聚合，门控残差叠加双曲分支
- 效果：-1.61pp（45.93%）
- 结论：无效

### 4.8 KDA（因果时间编码）
- flag：--kda
- 代码位置：FECNet.py:180-244（KDACausalEncoder）
- 实现：gated delta rule 递推，组内按时间戳排序后做因果状态更新
  S_new = Diag(α)·S_old − β·k·(k^T S_old) + β·k·v^T
  out = S^T q
- 问题：旧版梯度爆炸（ep24 被取消），修复F加了 self_in 防御断言
- 状态：续跑中（172275，从 ep24 续），不确定是否还会爆炸
- 背景：KDA 是大模型技术（Kimi K3 用它替代 ROPE），可能不适合小数据场景

### 4.9 MambaSSM
- flag：--event_mamba_ssm
- 实现：状态空间模型替代部分聚合，0.1 残差权重
- 旧版 bug：残差行 x=x+0.1*x_ssm 写两遍（实际0.2权重）
- 效果：修复后仍 0.00pp（与基线持平），方向放弃
- 结论：无效

### 4.10 SpikePoint 混合时间编码
- flag：--spike_time_enc
- 实现：保留 t 作坐标 + 额外 8 维 sin/cos（embed 12 维）
- 状态：首次测试，排队中（172204，A100）
- 来源：SpikePoint 论文

#### 6.3.1 【2026-10-13 18:32 新结果】双曲嵌入层判无效——对架构整合的直接影响

| 版本 | best test | vs 基线 47.537% | 真实含义 |
|------|-----------|-----------------|---------|
| 旧代码（171700，log∘exp 恒等 bug） | 48.608% | +1.07pp | 等价于 `LayerNorm(x + Linear(x))` 残差瓶颈 |
| **修复版（172206，真正双曲运算）** | **47.752%** | **+0.21pp** | **双曲部分零增益，反而低于 bug 版 0.86pp** |

**四条判断**：
1. **"双曲嵌入层（exp/log map）"作为独立组件判为无效**，+0.21pp 落在 ±3.2% 置信区间内，统计上不可区分于基线。
2. 旧版 +1.07pp 的**归因被推翻**：不是双曲几何，而是残差瓶颈结构。这一归因是**结构性的**，不依赖统计功效。
3. 与 172208（注意力+嵌入层）互相印证：ep51 已掉到 45.289%，**引入无增益的嵌入层使组合跌破基线**——嵌入层不是锦上添花，而是拖后腿。
4. **双曲主线的存活证据只剩两条**：双曲注意力（Lorentz 距离度量）、双曲选点（Poincaré 等双曲面积网格）。**架构整合阶段不应再押注"嵌入层 exp/log map"路径。**

## 十一、82.4% 复现谜团完整档案

### 11.1 结论
SECNet 官方 82.4% 是两阶段协议：
1. 先在单个 30ms 滑窗上训练 SECNet（单窗上限论文自测约 60%）
2. 再训练跨窗口聚合分类器（3×1080→1024→101）得到视频级结果

### 11.2 证据链
- 论文 Table 9：单窗（300ms）SECNet 只有 60.04%（8192点）/ 60.60%（10240点）
- README 原话："For CIFAR10-DVS and N-Caltech101, we first train SECNet on single sliding window, then train a simple classifier to get the results cross a sample."
- 官方 checkpoint 结构：attention(1,1080)、classifier 3240→1024→101（3240=3×1080，正是3窗口特征拼接）
- 本地代码结构：attention(1,540)、classifier 1080→256→101（与checkpoint不匹配）

### 11.3 官方代码缺陷
- train_frequency.py 的 num_category choices=[10,40] 跑不了 101 类

- 第二阶段聚合模型定义与训练脚本未公开
- 数据划分 np.random.shuffle 未设种子，不可复现

- GitHub 0 fork，6篇引用无复现报告，全网无第三方复现

## 十五、已知坑与经验教训大全

### 15.1 代码/实验坑
1. PowerShell 禁止内联 Python——必须写 .py 文件再 scp 上去跑
2. fish shell 不支持 bash for 循环和 heredoc——用脚本文件
3. ssh stdout 常被吞——用 > /tmp/file.txt 重定向再 scp 回读
4. grep 被 rg 别名替换——用 /usr/bin/grep 绝对路径
5. "b8+grad_accum4 等效b32"不成立——BN按micro-batch=8估计，只等效梯度
6. rp1 选点在 eval 时也是随机的（torch.rand），测试精度有噪声 <±0.5%
7. 日志 epoch 显示 bug：global_epoch 不自增，永远打 "Epoch 1 (N/60)"，不影响结果
8. checkpoint 现在存 args——换 flag 续跑会 loud fail，不会静默错配
9. gpu02 H100 弃用（CUBLAS 错误）
10. V100-16GB batch=32 OOM，只能 b8+grad_accum4
11. log_dir 必须全新——有旧 checkpoint 会触发 resume 校验，配置不匹配会报错
12. seq 投票 off-by-one：已修复 range(n-2)->range(n)，影响 <0.3%
13. **PowerShell 上传含中文的文件会把中文变成 `?`**——`Set-Content -Encoding ascii` 对多字节字符做有损替换（实测 1887 字节文件里中文全变 0x3F，HPC 侧 `file` 报 `ASCII text`）。含中文的 .py/.sh 上传必须用 `-Encoding UTF8`；给 HPC 上 Claude 的 prompt 建议**直接写英文**，避免编码坑。
14. **`/home/jnguan/zhangchenyuan/node/current/bin/claude` 是 `claude.exe` 的软链，但它是真的 Linux ELF**（`file` 确认 `ELF 64-bit LSB executable`），可直接用，不是 Windows 二进制。审查实测约 90 秒返回。
15. **并发实验的产物文件名必须包含所有变化维度**——踩过的坑：3 个推理作业并发、用不同 `eval_seed`，却都写同一个 `last.npz`，后写覆盖先写。结果分析时把"baseline 的 seed7"和"组件的 seed42"配对，p 值从 0.0097 变成 0.0609（假阴性）。修法：文件名带种子 `last_seed<42>.npz`。**固定文件名 + 并发 = 静默覆盖 = 假结论。**
16. **FPS 非确定性**：`models/modules.py` 的 `furthest_point_sample` 用 `torch.randint` 选起始点，**同一 checkpoint 的 eval 会在 ~2.6pp 内波动**。训练脚本只在开头设一次种子，训练持续消耗 RNG，所以**日志里每个 epoch 的 Test Accuracy 都是带噪声的单次采样**。评测必须固定 eval 种子（见 `tools/extract_preds.py --eval_seed`）。
17. **PowerShell 脚本必须纯 ASCII**：Windows PowerShell 把无 BOM 的 UTF-8 脚本按 GBK 读，中文注释会变乱码并直接导致解析失败（实测 `字符串缺少终止符`）。含中文的 `.py` 用 `-Encoding UTF8`；`.ps1` 一律写英文。
