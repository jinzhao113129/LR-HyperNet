## 一、16个点是什么

**G16 = 每个局部组选 16 个稀疏远程事件点（sparse remote events）。**

事件邻域不需要全局稠密 KNN，而是：

$$N_i = L_i \cup R_i$$

- $L_i$：dense temporal-local neighbors（时间局部连续的点，W384 = 384个）
- $R_i$：sparse selected remote events（稀疏选择的远程点，G16 = 16个）

核心思想：**Local continuity + non-local complementarity**（局部连续性 + 非局部互补性）

## 二、关键实验结果

| 方法 | Seq Acc | Latency | 含义 |
|---|---:|---:|---|
| Global Feature-KNN | 66.70% | 11.38 ms | 全局特征KNN，强但贵 |
| Local W384 | 59.30% | 1.58 ms | 纯局部，快但信息不够 |
| Random remote | 59.87% | — | 远程点不能乱选 |
| Time-polarity | 60.10% | — | 简单时间先验不够 |
| Spatial-uniform | 61.08% | — | 空间补充有一定价值 |
| **Oracle W384-G16** | **68.03%** | — | **16个高质量远程点超过Global KNN** |

- Local W384 → Oracle W384-G16：**+8.73 个点**（59.30% → 68.03%）
- Oracle 甚至超过 Global Feature-KNN（68.03% > 66.70%）
- **结论：远程点怎么选比选多少更重要**

## 三、和我们当前架构的关系

### 我们的代码
- `RemoteSelector` 中 `remote_g=16` —— 就是这个 G16
- 当前用**欧氏特征距离 top-16** 选远程点，相当于 Global Feature-KNN 思路
- 选完后在双曲空间做聚合（HyperbolicRemoteAggregator）

### 差距
- rp1 证明 Oracle 选点（68.03%）> Global KNN（66.70%）
- 我们用的是欧氏 KNN 选点，不是最优
- 学长说的"16个点怎么找"就是指：**能不能用比欧氏 KNN 更聪明的方法选这16个点**

## 四、可探索的选点方法

rp1 文档列出的 selector 候选：

| Selector | 说明 |
|---|---|
| Random | 随机选（基线，证明不能乱选） |
| Spatial-uniform | 空间均匀采样 |
| Time-polarity | 时间+极性先验 |
| Feature hash | 特征哈希快速选 |
| **Learned scorer** | 可学习的打分网络 |
| Oracle | 最优选择（上限） |

### 对我们最直接的探索方向

1. **双曲距离选点**：在双曲空间里算距离选 top-16，而不是欧氏距离
   - 学长原话："压在双曲里面，它可能特征会有其他的一些想法"
   - 改动很小：把 RemoteSelector 里的欧氏距离换成双曲距离
   - 可以和欧氏选点做严格对照

2. **可学习 selector**：用一个小网络给候选远程点打分，端到端学习
   - rp1 里的 learned scorer 方向
   - 工程量稍大，但可能增益更大

3. **远程点 profiling**：分析什么样的点是"好远程点"
   - 空间新颖性、时间跨度、特征余弦相似度、极性一致性、局部密度、轮廓各向异性、空间覆盖增益
   - 先分析再针对性设计选法

## 五、rp1 提出的评估维度

不是只比 accuracy，而是三维 trade-off：

$$\text{Accuracy} \quad \text{vs.} \quad \text{Oracle Recall@G} \quad \text{vs.} \quad \text{Latency}$$

- Oracle Recall@G：选出来的 G 个点中有多少是 Oracle 选的点
- Latency：选点的计算开销
- 目标：用便宜的 selector 逼近 Oracle
