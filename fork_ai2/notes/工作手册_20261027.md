## 2. 3090 上怎么跑训练

### 2.1 标准启动模板
```bash
cd ~/zhaojin/pi2 && PYTHONPATH=$PWD:$PWD/models:. nohup ~/zhaojin/venv/bin/python \
  tools/train_frequency_ncaltech.py \
  --data_path ./data/ --num_point 10240 --batch_size <B> --grad_accum <A> \
  --epoch 300 --patience 20 --early_stop_metric acc \
  --learning_rate 0.001 --optimizer AdamW --decay_rate 0.0001 \
  --num_category 101 --log_dir <log_dir> --log_path ./log/ --log_name /<log_dir> \
  --augment 3 --ema 0.999 --seed 42 <组件 flags> \
  > ~/zhaojin/logs_run/<name>.log 2>&1 &
```
- 显存紧张时加 `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`。
- 常用组件 flags：`--remote_g16 --g16_treatment <t>`、`--hyperbolic_gate`（hgate）、
  `--fca_gate`、`--polar_feature`、`--covariance_channel` 等。
- G16 treatment 合法值：`random / spatial_fixed / euc_far / euc_near / hyp_far / hyp_near /
  rp1_scorer / cosine_near / learned / learned_v2 / global_knn / csnet`。

### 2.2 看进度
```bash
date; pgrep -af "train_frequency_ncaltech" | head -3; nvidia-smi --query-gpu=memory.used,utilization.gpu --format=csv
```

```bash
grep -a 'Epoch 1 (' ~/zhaojin/logs_run/<name>.log | tail -1
grep -a 'Test Accuracy:' ~/zhaojin/logs_run/<name>.log | tail -4
grep -a 'best test acc' ~/zhaojin/logs_run/<name>.log | tail -1
grep -a 'EarlyStop' ~/zhaojin/pi2/log/classification/<log_dir>/logs/pointmlp.txt | tail -1
```

### 2.3 停 / 串联
```bash
pkill -f "<log_dir 关键字>"
```
- 串行链：`~/zhaojin/pi2/run_remaining_chain.sh`（fca → polar → g16_cosine），靠
  `.done` 标记断点续跑；watchdog 用 `wait_and_run_learned.sh`（等链退出后起下一条）。
- 早停判断：`EarlyStop: no improvement for N/20`，剩余时间 ≈ `(20−N) × 单轮耗时`。

### 2.4 显存/速度经验（N=10240，24GB 卡）
| 配置 | 显存 | 单轮耗时 |
|---|---|---|
| batch 16 / accum 2（无 G16、fca 等） | ~21.5GB | ~9 分钟 |
| batch 8 / accum 4（G16 固定选点，如 cosine_near） | ~15GB | ~16 分钟 |
| batch 4 / accum 8（learned_v2，M=256） | ~17.6GB | ~60 分钟 |
| batch 2 / accum 16（csnet，M=256） | ~18.6GB | ~84 分钟 |
| batch 4 / accum 8（csnet，M=128，chunk 64） | ~18.4GB | ~60 分钟 |

- csnet 在 M=256 下：batch 4 / 3 都 OOM，只能 batch 2。
- learned/csnet 的 M 由 `--learned_M` 控制（默认 256），csnet 注意力块由 `--cs_chunk` 控制。
- csnet 的 OT 温度由 `--cs_tau` 控制（**2026-10-27 起从硬编码改为命令行参数**，默认 0.1），
  会写入 saved args、纳入 resume 校验；推理 `extract_preds.build_model` 用 `.get(cs_tau,0.1)` 重建。
- 经验：M 从 128→256，显存约 +3~4GB；cs_chunk 只影响峰值，不改变总注意力显存。
- 启动自检：模型构造时每个 stage 打印一行 `[G16-SELECTOR] ...`，csnet 会显示
  `soft_topk=entropy-OT cs_tau=... learned_M=... cs_chunk=...`，用于确认真跑的是 OT 选择器
  而不是旧代码（见第 8 节第 9 条）。

### 6.2 G16 选点（24 局部 + 16 远程，远程聚合成 1 向量）
| treatment | 结果 | 备注 |
|---|---|---|
| cosine_near | 60.493% | 余弦最近；最佳固定规则 |
| rp1_scorer | 59.64% | 特征最近 + 空间新颖 |
| euc_near | 59.10% | 欧氏最近 |
| euc_far / hyp_far / hyp_near | 44 / 46 / 44% | 方向错/双曲选点证伪 |
| learned（LapSum，ep15） | ~40% | 可学习线，未追平固定 |
| learned_v2（GAT + 4 信号，ep1） | 22.06% | 已停，未继续 |
| csnet（EOT，M=128，tau=0.5） | ep5 test 21.5 / train 21.9 | 已停；tau 0.1 重测中 |

### 6.3 几何分析（先找点）
- 方法：`scripts/local_edit/selector_geometry_dump.py`，dump 中心 + 特征最近 16 远程点 +
  局部 24 + 随机 16，存 npz 后统计。
- stage0（4 通道输入）：有效秩 3–4/64，远程 cos 0.995——必然结果。
- stage1/2（G16 cosine checkpoint）：有效秩 11.1/15.2；远程点彼此 cos 0.70/0.65，
  局部 0.79/0.77，随机 0.07/0.06。
- 空间新颖性：远程 0.062/0.145，随机 0.596/1.263；时间跨度 0.289/0.181 vs 0.322/0.219。
- 结论：按特征最近选出的"远程点"在空间上紧贴局部邻域，**不是真远程**；
  这比"余弦 vs 欧氏"更能解释 59–60。

### 6.4 RP1 事实（已核对原码）
| 方法 | 数字 | 度量 |
|---|---|---|
| Global Feature-KNN（SECNet 基线） | 66.70% | 平方 L2（`_global_knn` → `square_distance`） |
| Oracle W384-G16 | 68.03% | 平方 L2（窗外精确搜索） |
| Local W384 | 59.30% | 时间窗 |
| Spatial-uniform | 61.08% | 固定规则（已验证 cheap selector 最好） |
| block_retrieval | 未验证 | 文档明确 no accuracy claim |

- RP1 数据：N-Caltech101，2048 events/sample，train 20901 / test 5226，101 类；
  group=512、neighbors=24、base_dim=16。
- 66.70 不是 cosine；G16 该对标 Oracle 68.03，不是 66.70。

## 8. 常见坑

1. **OOM**：24GB 卡上 learned/csnet 的 M=256 只能 batch 2；M=128 可 batch 4。
   报错往往是最后 68–402MB 的分配失败，不代表就差这么多。
2. **中文用户名**：Git Bash 里 ssh/scp 找不到 `~/.ssh`；用 Windows OpenSSH +
   `MSYS2_ARG_CONV_EXCL='*'`。
3. **路径转换**：Git Bash 会把 `/home/...` 转成 `D:/...`；ssh 远端命令必须关掉转换。
4. **粘贴断裂**：多行命令粘到终端可能被截断（出现 `syntax error near '('`），
   重贴为单行；grep 模式用单引号。
5. **代理开关**：拉 raw 文件不要开代理；git pull 必须开代理，且梯子要在。
6. **resume 校验**：新加的训练参数（`base_dim/fps_groups/learned_M/cs_chunk`）已加入
   校验键列表；换宽度/池子恢复会报错而不是静默崩。
7. **推理重建**：`extract_preds.build_model` 已按 `base_dim/fps_groups/learned_M/cs_chunk`
   重建；新增可学习组件记得同步这里，否则 strict load 失败。
8. **训练 acc 才是判断"学没学"的指标**：test 低可能是失配，训练 acc 也低才是优化/结构坏了。
9. **gpu 机代码可能是旧版，作业会静默用旧选择器**（2026-10-27 实踩）：pi2 是组装目录，
   改了 GitHub/`local_edit` 后必须在 gpu 重新拉取 + 覆盖 `pi2/models|tools`，否则
   `--g16_treatment csnet` 这类新 flag 会落到旧分支。重启前务必 grep 部署文件里的关键标记，
   并看日志 `[G16-SELECTOR]` 自检行；硬编码超参（如旧 cs_tau）不进 Namespace，无法审计，
   所以新超参一律做成 argparse 并加进 resume 校验键。
