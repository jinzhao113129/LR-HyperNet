## 0.5 逐组件替换路线图（2026-10-17 学长拍板，核心章节）

**学长指示原文（金朝转达）**：
> 新的 SOTA 从来不是在旧网络上加几个组件完成的——不要在 SECNet
> 上面胡搅蛮缠，大胆一点。就做那 16 个点加上双曲的变换，加自己
> 的创新点，或加三篇文章里的创新点。大胆换掉 SECNet 的架构——
> 核心可以不用换（比如傅里叶变换可以保留），其他的可以全删掉。
> **一步一步把 SECNet 的组件替换掉。**

**路线优势（学长看中的）**：
1. **风险可控**：每步只动一个变量，涨跌归因明确——比新骨架
   一次性全暴露稳；
2. **归因干净**：每步配对差 = 该替换的净贡献，论文消融表
   就是替换链条本身；
3. **复用已跑资产**：175245（70.36%）、ha 链、G16 链的结果
   直接成为替换链的起点与证据；
4. **训练配方继承**：底座不变，lr/epoch/增强配方一路继承，
   无新骨架 1.5-2× 重调成本。

**替换顺序（每步一条链，过 Codex 审，配对差归因）**：

```
底座：SECNet 双曲选点版（70.36%/72.56%；增强版底座在跑）

  ① 聚合层：傅里叶 → 双曲注意力
     （ha 增强链正在跑的就是这一步的替换效果！）
  ② 采样层：FPS 分层 → 16 点远程选择组织
     （G16 hyp_far 链在验证选择准则；fps_parameter 改造纳入）
  ③ 融合层：gated fusion → 双曲距离加权融合
     （三件套贯穿——第三个"双曲发生作用"的位置）
  ④ 分类头 → 欧氏 MLP（HexFormer-Hybrid 证据）或双曲原型（消融）
  ⑤ 3-stage 结构 → 保留思想换实现（最后一步，壳完成——
     "看不出 SECNet" 到此达成）
```

**与"一次成型"的对比与决策记录**：一次成型（纯 MLP 骨干从零搭）
查新叙事更利落，但风险一次性暴露、配方全重调、已有实验资产贬值；
逐组件替换每步可验证可归因，学长拍板选后者。**每步替换完的中间态
不对外称为新架构，只是演化过程；论文的新架构 = ⑤ 完成后的形态。**

**傅里叶的地位（学长特别指出）**：可以保留——它是通用工具非 SECNet
识别特征（帧类方法也在用频率域），留在局部聚合支路。

**论文叙事衔接**：替换链的终点（⑤）+ 三件套贯穿 + 16 点核心 =
愿景公式达成。中间每步的配对差表 = 论文的组件消融大表（天然生成）。

## 2. 双曲贯穿三件套的落地设计

### 2.1 选点层（第一件）

G16 六处理实验的数据将直接决定：
- 若 hyp_far 最强 → 双曲距离选点进新架构（学长核心创新直接落地）
- 若 euc_near 最强 → KNN 方向 + 双曲聚合（选点欧氏、聚合双曲的分工）
- 若 spatial 最强 → 覆盖优先（双曲退到聚合+分类头两件）

**设计占位**：`HyperSelector` 模块——输入 [B,N,C] 特征 + [B,N,4] 坐标，
输出每中心 G 个远程索引。内部准则等 G16 数据定。

### 2.2 聚合层（第二件）

双曲注意力链的数据（B）将验证：6 标量零投影的 Lorentz 距离注意力
是否真有效。若有效：
```
新聚合 = 双曲距离注意力（零投影版）逐层替代 MLP/傅里叶聚合
       → 整个骨干的"注意力"全部发生在双曲空间
```
零参数几何先验的形态（论文卖点）：骨干不是"加了个双曲模块"，
是"几何本身换了"。

**堆叠稳定性约束（Codex HexFormer 深读结论，2026-10-15）**：
文献支持"12 层双曲注意力可行"，但**不是朴素堆叠**。Codex 深读
`codex_hexformer_stability_20261015.md` 的底线设计规则：

> 平方距离打分（squared Lorentz distance，不直接 arccosh）+ 切空间
> ExpAgg 聚合（避免 Lorentz 质心分母坍缩）+ 固定共享曲率（先不学
> 每层曲率）+ 欧氏/hybrid 分类头（而非全 Lorentz MLR 头）+ 分阶段
> 深度诊断（3→6→9→12 smoke pilot）。

对我们零投影注意力的具体约束：
1. **不能默认我们的 6 标量零投影注意力能堆到 12 层**——HexFormer
   的 12 层靠 LorentzFC 投影 + Lorentz BN + pre-LN + ExpAgg 全套机制，
   我们是更极简的机制，稳定性未验证；
2. **当前 3-stage 就是 depth-3 基线**，多层化必须先跑 6/9/12 的
   smoke pilot（配逐层诊断：激活半径/内积有效性/arccosh 余量/
   注意力熵/梯度范数/NaN 计数），不能直接写进核心架构声明；
3. **hybrid 头是更强默认**（HexFormer-Hybrid 一致优于全双曲），
   Lorentz 原型头降为消融，不是主路径——这与 §2.3 的 P0 判无效
   一致（双证指向：分类头用欧氏，双曲价值在选点+聚合两层）。

**HexFormer 关键数字**（供设计引用）：Tiny 9 层 / Small 12 层 /
Base 12 层均稳定；9 层 centroid 聚合 + 普通 AdamW 下 4/5 seed
NaN 崩溃，换 ExpAgg 后 5/5 完成——**"深度 × 聚合方式 × 优化器"
三者联动才是稳定性边界**，不是单一深度上限。

### 2.3 分类头（第三件）

已有 `HyperbolicPrototypeClassifier`（Lorentz 原型分类）。
P0 曾判无效（坏基线）——全量上重测一次再定去留。

### 2.4 叙事（论文的灵魂句）

> "我们不把双曲几何当作一个可插拔模块，而是把它作为事件点云的
> **原生几何**：远程信息在双曲空间里被选择（选点）、被聚合（注意力）、
> 被分类（原型）——整个信息通路发生在同一个几何里。"

## 8. 组件组合策略（2026-10-15 补，学长分享的 ICML 论文启发）

**来源**：Hedging on the Frontier（Wegel et al., ICML 2026, arXiv 2605.30997）。
原文已存 `D:\论文\2605.30997_Hedging_on_the_Frontier.pdf`。

**可引的一句话视角**：把"组件组合"看作**帕累托前沿上的选择问题**，
而非贪心叠加——被支配的组合（加了某组件 acc 不涨还涨成本/复杂度）
直接排除，只在前沿上权衡。

**落地到阶段四（减法消融 → 最终架构）**：

| 维度 | 我们的映射 |
|---|---|
| 论文的"模型" | 我们的"组件组合"（双曲选点/双曲注意力/RP1 scorer/可学习缩放/分类头…） |
| 论文的"基准风险" | 我们的多目标：test acc、seq acc、泛化 gap（train-test）、参数量/训练成本 |
| 论文的"帕累托前沿" | 非支配组件组合的集合——支撑 2×2 交互矩阵已证"组件有交互，不能线性叠加" |

**操作含义**：
1. 组件组合评估用**多目标**记分，不只比 test acc 单点；
2. "某组件加了没用还加复杂度" = 被支配 → 直接砍，不必跑全组合；
3. 最终架构 = 前沿上的一个点（权衡），不是"所有有效组件全堆"。

**定位**：这是 Related Work / 方法论的**一句话引用**，不是核心依据；
理论部分（覆盖数/模量/快速率）对我们的场景不适用，不深读。

## 10. 几何审计落地（2026-10-16，Codex 深读，防"双曲只是装饰"质疑）

**来源**：`notes/codex_audit_deepread_20261016.md`（生死文献 2607.05268
的可执行改编）。核心：**测量有效几何工作点**，不是报标量曲率。

**核心量**：`u = √c · ρ`（ρ=Lorentz 空间范数）、`H(u)=u/asinh(u)`。
阈值：u>0.84 = 局部度量畸变超 10%；u>1 = 保守"非局部双曲"标记。
**陷阱**：标量 c 会塌缩而 ρ 增长补偿，u 不变——所以必须报 u 而非只报 c。

**三处 hook**（selector / 远程聚合器 / 双曲注意力），各自记录 u/H/c/内积误差。
opt-in `--geometry_audit` flag + `geometry_audit_agent.py`（不常驻 profile sink）。

**profile agent 分离度"有用但不够"**（Codex 判定）——reviewer 会说
"选点不同是因为打分函数不同，不等于径向曲率活跃"。必须补：
1. u/H 统计（selector + 聚合器）；
2. **欧氏 vs 双曲距离排序 Kendall τ**——若 τ≈1 说明双曲只是欧氏的单调变换；
3. 曲率扰动（c_eff ∈ {0.5c, c, 2c} 看选点/预测/u 是否不变）；
4. matched 固定/可学习曲率 + floor release 对照。

**2×2 交互效应（7.6pp）的弱点**（Codex 逐条）：单种子、网格离散结构混杂、
缺 u 审计、无匹配欧氏网格密度。**升级要求**：seed 7/13/42 + 配对 McNemar
+ 预注册 + 两臂都跑 u 审计 + 匹配欧氏径向密度对照。

**5 个 reviewer 攻击 + 逐条回应**已在 Codex 文档——写论文前必须能对答。
**执行顺序**：先写 geometry_audit_agent.py → 跑现有 smoke checkpoint →
加曲率扰动/floor 对照 → 校准阈值 → 所有强声明在 official_gen + 3 seed
上重跑后才落笔。
