# 坐标感知采样/扫描诊断 pilot 设计（2026-10-14，承接 Codex 主线推荐）

背景：Codex 文献扫描（codex_review_20261014.md "Project-line research scan"）推荐
主线新方向 = **坐标感知采样/扫描**——直接承接项目已有证据（FPS 坐标缩放改变中心
分布、fps_parameter 漂移 = SECNet 隐藏组件），与 EventMG 的 APN 学习式坐标扰动
扫描同族。先低成本诊断、证据支持后再训练新组件。

## 1. 为什么这个方向承接现有证据链

项目已有三块拼图：
1. **A1 归因修正**：基线自身 fps_parameter 训练后漂移（x~1.64x）——SECNet 原生
   就在"学习坐标缩放"（等价于逐维 affine 缩放选点）。
2. **2×2 交互效应**：双曲网格在缩放坐标下 +4.71pp、欧氏网格在缩放坐标下 -2.89pp
   ——"什么坐标做采样"和"什么几何做采样"存在交互。
3. **Codex #5**：grouper 返回的 new_xytp 是已缩放坐标的邻域均值，逐 stage 传递
   ——坐标变换是跨 stage 复合的，从未被仪器化观测。

EventMG APN 的本质：**Tanh 有界逐事件坐标扰动** (Δx,Δy,Δt) = Tanh(MLP(h))，
学习一个"有效坐标空间"再扫描。它证明"学习式坐标变换对事件数据有效"——但我们
不需要 Mamba/图，只需要检验"SECNet 的 FPS 坐标空间是否可学习改进"。

## 2. Pilot 设计（固定 checkpoint，零训练，低成本）

**研究问题**：固定已训练 checkpoint（基线 seed42），不同的逐轴仿射坐标缩放
(sx, sy, st)（含 fps_parameter 学到的实际值与人工网格）如何改变 FPS 中心点分布
（覆盖/重叠/网格占用）与类别预测（翻转样本的类别分层）？若存在系统性"好缩放"，
则"学习有效坐标空间"是值得训练的组件；若预测对缩放不敏感，则方向证伪。

**诊断器**（复用现有工具，全部固定 seed42）：
1. **中心分布指标**：对 934 测试样本跑 FPS（同一 randint 种子），比较不同 (sx,sy,st)
   下的中心点：4×4/8×8 网格占用、中心间平均距离（覆盖）、IoU（稳定性）。
   Codex #4 的 clamp 率/越界率一并记录。
2. **类别分层预测变化**：用 extract_preds.py 的既有协议，扫 (sx,sy,st) ∈
   {0.5, 1, 1.64(实测fps_parameter值), 2}³ 的稀疏网格（~27 点，每点 934 样本推理，
   CPU 不可行 → GPU 单作业 2h 内），记录 per-sample 预测翻转与 acc 曲线。
   2×2 的核心假设"缩放改变选点分布"在这里变成可测曲线而非两点。
3. **对照**：基线 checkpoint 的 fps_parameter 实际值（需从 checkpoint 读出，A1 实测
   x~1.64）作为"学到的缩放"锚点 vs 未学习的人工网格。

**修正（2026-10-14 16:58，Codex 指出两处设计缺陷）**：
1. **网格规模**：原文写 `{0.5,1,1.64,2}³ = 27 点` 是算术错误——4 值/轴
   三轴 = **64 组合**。改为预先声明的稀疏网格：
   - 主网格 `{0.5, 1, 2}³ = **27** 组合（3 值/轴，真 27）；
   - 锚点追加 3 个具名点：`(1.64,1.64,1)（实测 fps_parameter x/y 值）、
     (1,1,1) 恒等、训练学到的实际 (sx,sy,st) 全向量 → 共 **30 组合**。
2. **数据泄漏防护**：不得用 934 测试集筛选缩放。改为：
   - 诊断主体在**训练划分划出的验证子集**（或训练集 10% 留出）上扫
     30 组合；
   - 934 测试集只做**预注册的事后确认**：验证集选出 top-1 缩放后，在
     测试集上评一次，不做任何挑选；
   - 判据主指标改为验证集 acc，测试集只报告。
3. **机制指标同步记录**（Codex #4/#5）：每 (sx,sy,st) 记各 stage 的
   pre/post 坐标范围、clamp 率、中心点 4×4 占用格数——覆盖与 acc 的
   关联才是机制证据。

**判据（预先声明，修正版）**：
- 支持：验证集上存在 (sx,sy,st) 使 acc 显著 > (1,1,1)（同一 checkpoint
  配对比较），且中心分布指标与 acc 变化单调关联（机制证据）→ 提议 APN
  式可学习缩放的训练实验（参数预算匹配对照：fps_parameter 本身就是
  4 维可学习缩放，APN 是逐事件 MLP 版）。
- 证伪：验证集 acc 对 30 组合不敏感（±0.5pp 内），或中心分布变化与
  acc 不关联 → 记录结论，方向关闭，避免无机制支撑的大组件移植。
- 测试集结果无论好坏只写进报告，不反馈到任何决策（防泄漏）。

**成本**：1 个 GPU 作业（推理级，~1-2h），不动训练。判据预先声明防止事后挑好的。

**注意**（Codex 边界）：
- 不移植 APN 全模块（六向扫描+图聚合），只测坐标空间假设——EventMG 的任务/
  图构成都不同（Codex 原话）。
- 2×2 结论仍是单 seed 假设（Codex #3），本 pilot 用固定 checkpoint 消除训练
  方差，是它的低成本补充而非替代。
- 频域/时间编码的去重审计（Codex 推荐的并行任务，HoloEv-Net/Event2Vec 对照）
  待 pilot 出数据后排期——同一批 934 样本诊断可复用。

## 3. 实现路径（不动运行中作业）

- 诊断脚本放 `ai2_g16/`（隔离目录惯例）或 fork_ai2/scripts/ 下新 ai2_coords/：
  读 checkpoint → 读 fps_parameter 实际值 → 扫缩放网格 → NPZ 输出
  （log_dir 风格命名：coords_pilot_seed42.npz，含每 (sx,sy,st) 的 934 预测）。
- 需要一个小的 extract_preds 侧入口：不做模型侧改动，用 hook/包装在推理时对
  输入 xytp 做逐轴缩放（等价于推理时改 fps_parameter——注意 A1 发现 fps_parameter
  是模型参数，推理时覆盖它即可，无代码侵入）。
