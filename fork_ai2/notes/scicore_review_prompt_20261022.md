# Science Core 审稿 prompt（2026-10-22）

> 来源：RobustReview / SciCore（arXiv 2609.39027，弗吉尼亚理工 / 马里兰 / MBZUAI）。
> 核心结论：反复 prompt 模型"只关注科研内容"**不能**稳定提升审稿质量（论文实测
> Claude Sonnet 5 用这招 ICC 反而从 0.579 掉到 0.489）；有效做法是**两阶段**——
> 先抽取一份对措辞鲁棒的"科学内核"（Science Core），再对照内核审稿。
>
> 用途：投稿前把论文交给 Codex / Claude 做一轮独立审稿。复制下方【审稿指令】，
> 把 `{论文路径}` 替换成实际文件即可。接进现有论文检查纪律（[[paper-review-report-only]]）
> 时，用它替代"审论文 + 强调只关注科学"的一步式 prompt。

## 为什么两阶段

论文实测：同一篇论文换 20 种写法，GPT-5.5 抽取的 Science Core 与原稿在文本嵌入空间
余弦相似度 **0.978**；与其他论文的 Core 相比约 **0.62**。即"研究问题 + 方法 + 数字 +
复现信息"这一层对措辞高度稳定。先把它抽出来，审稿就能少受写法干扰。

同时这也是一份**投稿前自查清单**：自己先跑一遍抽取，等于把"每条 claim 有没有证据、
消融对照够不够"过一遍筛。

## 审稿指令（直接喂给 Codex）

```text
你是一名论文审稿人。请严格按下面两阶段流程审阅这篇论文（{论文路径}），
不要跳过第一阶段，不要一步式地"读论文 + 给分"。

【第一阶段：抽取 Science Core】
从论文中提取一份"科学内核"——这是客观的结构化记录，只记录论文报告了什么，
不评价质量。包含五部分：

1. 研究问题：论文要解决什么问题，目标是什么。
2. 方法与假设：提出的方法、关键公式、模型结构、以及作者明确声明的假设。
3. 实验结果：所有主结果表、消融表、对照实验的数值，逐项转写。数字、单位、
   对比基准全部原文保留，不要四舍五入、不要改写、不要合并。
4. 复现信息：数据集、训练/评测协议、超参数、随机种子、硬件。
5. 作者声明的局限：论文自己承认的局限。

提取纪律：
- 关键公式和具体数值原文照抄，实验表格完整转写。
- 读不清的地方明确写"无法从文中读取"，不要臆测补全。
- 本阶段只记录"论文声称了什么"，不判断真假、不判断好坏。

【第二阶段：对照 Science Core 审稿】
基于第一阶段的内核，逐条回答：

1. 证据充分性：每条核心 claim 是否有足够证据支撑？
   对每条 claim 指出：支撑它的实验 → 证据是否够 → 缺什么。
2. 对照与消融：实验对照和消融是否充分？缺哪些关键对照？
3. 数字自洽性：正文、表格、摘要、图注里的同一个数字是否一致？逐处核对。
4. 问题归因，必须分成两类分别列出：
   - "论文缺少证据"：真问题，必须改。
   - "我提取失败/读不清"：可能是论文没写清，也可能是我的误读，
     单独标注，让作者确认后再说是不是问题。

输出格式：按 P0（阻断：claim 无证据 / 数字矛盾 / 缺关键对照）/
P1（应补强）/ P2（建议）三档列问题，每条给出定位（章节 / 表格 / 公式编号 + 原文引用）。

硬性约束：
- 不因写法、句式、措辞、篇幅挑刺或给分，只评科学内容。
- 每条问题都要能回到论文原文定位，不能是印象式的"感觉这里弱"。
- 你的结论要能通过"这篇论文换个写法再审一遍仍是同样结论"的检验。
```

## 与我们现有纪律的衔接

- **只报告不修改**：这个 prompt 输出的是问题清单，不是改稿；沿用
  [[paper-review-report-only]] 的默认（除非用户明确要动手改）。
- **数字逐条 grep 核对**：第二阶段第 3 条（数字自洽性）是对
  [[paper-review-report-only]] 里"修复总结常与文件不符、必须 grep 逐条核对"
  的正面强化——审稿和复核都用"回到原文核对"这一招。
- **三档与 Codex 审 G16 同款**：P0/P1/P2 沿用 `codex_review_g16_20261021.md`
  的格式，和双人制审查的输出口径一致。
- **别在 prompt 里加"focus on science"当保险**：论文实测这招不稳定，不要靠它；
  要抗写法干扰就老老实实走两阶段。
