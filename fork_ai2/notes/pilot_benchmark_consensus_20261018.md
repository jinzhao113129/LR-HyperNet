## 2. 为什么快测必须跑 base（配对差锚）

用户曾质疑"不是直接对照 60.6 吗，为何还跑基线"。共识如下：

- 60.6 是**官方训练版**跑出来的，内含其未公开组件红利；我们 fork
  公开版同协议历史基线只有 47.5-54.1。组件链若直接 > 60.6，差值里
  混着"组件贡献"与"配方贡献"（增强×4 + EMA 官方没有），无法归因；
- 同配方 base 把配方效应两边抵消，**配对差 = 组件净增益**——这是
  Codex 快测复审恢复被砍 base 链的原因（changelog §36 P0-1）；
- 60.6 未被抛弃：仍是小批量同格式的外部水平参照 + 全量前的量级
  sanity check。判定方式从"一超定胜负"升级为"配对差筛方向 →
  全量对表"，加的是归因严谨层，不是换靶子。

## 3. 统一配方（6 链一致，唯一变量 = 组件）

| 配方项 | 设定 | 来源/依据 |
|---|---|---|
| 数据增强 | augment 3（每样本 3 个增强版本，五选 2~3 叠加，数据 ×4） | 官方是 2 变体（crop+reverse→×3），我们多 1 个增强版本；EventRPG（SNN 85.62）近半增益背书；用户 10-17 拍板"所有链都上" |
| EMA | 0.999（step 粒度，checkpoint 持久化） | 我们加的（官方无此配置），量级 +0.5~1.5pp；属"配方"非"组件" |
| 早停 | patience 20（--early_stop_metric acc）+ epoch 300 上限 | 小样本收敛快（实际 60-150ep）；口径 = 官方 Table 9 单窗 test acc |
| batch | 16 + 梯度累积 2（等效 32） | 对齐官方 batch 32 |
| 优化器 | AdamW lr=1e-3, decay 1e-4 | 对齐官方 |

**配方与官方的对齐度**：增强×4/轮数/优化器/batch 对齐；EMA 是我们的
额外优势；数据量是官方 1/17（小样本协议）。因此**绝对值不可跨配方直比**，
配对差可信，全量出数后才跟 60.6/82.4 对表声明。
