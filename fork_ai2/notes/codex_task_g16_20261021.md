## 三、接线设计

FECNet 采样层创建分支（每 stage）：

```python
if use_remote_g16:
    local_grouper = LocalRemoteGrouper(self.feature_list[i], self.group_number[i],
                                       kneighbors=24, remote_g=16,
                                       use_xyz=True, normalize="center",
                                       use_hyperbolic_selector=True,
                                       hyperbolic_type="lorentz",
                                       selector_mode="topk")
elif use_rp1_selector: ...
elif use_hyperbolic_selector: ...
else: LocalGrouper(...)
```

G16 标准配置：`remote_g=16` + **双曲距离选点（lorentz）** + topk。互斥：`use_remote_g16`
与 `use_rp1_selector`/`use_hyperbolic_selector` 同层采样、三选一，`__init__` 显式 ValueError。

## 五、审查要点

### P0 正确性

1. **LocalRemoteGrouper 参数传递**：`__init__` 签名是 `(channel, groups, kneighbors=24,
   remote_g=16, use_xyz=True, normalize="center", ...)`——注意 `remote_g` 在 `use_xyz`
   **之前**。我最初用位置参数传导致 remote_g 被赋 True 报错，已改关键字参数。请复核
   当前关键字传参是否与签名逐项对齐（尤其 kneighbors/remote_g/use_xyz/normalize）。
2. **use_hyperbolic_selector 语义冲突**：`LocalRemoteGrouper(use_hyperbolic_selector=True)`
   是"远程选点用双曲距离"；而 FECNet 自身的 `use_hyperbolic_selector` 是"采样层换
   HyperbolicUniformGrouper"。两个同名 flag 含义不同，是否会混淆？接线是否传对？
3. **形状兼容**：LocalRemoteGrouper 输出维度是否真的与 LocalGrouper 一致（2C+4），
   下游 FFT/聚合/门控融合无需改动？（我 forward 跑通，但请独立验证各 stage 形状）
4. **显存**：batch16 + grad_accum2 训练时，RemoteSelector 的 [B,S,N] 分块距离矩阵
   峰值显存是否真能放下 24GB？（我只测了 batch2，外推有不确定性）

### P1 设计风险

5. **selector_mode="topk" 是否是最该先跑的模式**：G16 有 topk/greedy_div/random/
   spatial_uniform 四种。先跑 topk（特征距离选点）是否合理，还是应先跑 spatial_uniform
   作基线对照？
6. **remote_g=16 的语义**：16 个远程点 + 24 个局部邻居，输出维度 2C+4 里远程聚合
   特征是否真替代了中心点特征（而不是冗余拼接）？

### P2 建议

7. 命名一致性（`use_remote_g16` vs 代码里 LocalRemoteGrouper 的 `remote_g`）；是否
   需要在 chain_flags 注释里说明 g16 是"采样层远程选择"。
